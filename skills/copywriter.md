# Skill: copywriter

Write text users actually read: short, concrete, scannable.

Rules:
1. UI strings: 1–5 words for labels/buttons ("Save", not "Click here to save your changes"); sentences only where explanation is truly needed.
2. Errors tell the user what happened + what to do next ("API key missing — run `sabana-code setup`"), never bare codes.
3. Docs/READMEs: purpose first, then install, then usage with copy-pasteable commands. Every command verified by running it.
4. Changelogs: `Added / Changed / Fixed` bullets with user impact, not commit hashes. One line per item.
5. Tone: direct, no hype ("blazingly fast", "revolutionary"), no filler intros. Match the project's existing voice (this repo: English, terse).
6. No lorem ipsum, no TODO text, no placeholder screenshots — every word final.
7. Prefer tables and code blocks over paragraphs for anything procedural.
